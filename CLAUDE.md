This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Samet's personal website: a Next.js (App Router) app using shadcn/ui (Nova style, Neutral base color, Inter font), statically exported and hosted on GitHub Pages (`smtnkc.github.io`). Deploys via `.github/workflows/deploy.yml` on push to `main` (build + `actions/upload-pages-artifact` + `actions/deploy-pages`) — the repo's GitHub Pages source must be set to "GitHub Actions" (not the legacy Jekyll auto-build) for this to take effect.

This replaced a previous zero-build Jekyll site. There is no Jekyll, Ruby, or Liquid left in this repo.

## Commands

- **Dev server**: `npm run dev`
- **Production build (static export)**: `npm run build` — outputs to `out/`, driven by `output: 'export'` in `next.config.ts`. Serve it locally with any static file server (e.g. `npx serve out`) to spot-check the exported HTML.
- **Type check**: `npm run typecheck`. **Lint**: `npm run lint`. **Format**: `npm run format`.
- Add shadcn components with `npx shadcn@latest add <component>` — this project uses the **Base UI** flavor (`components.json` → `"style": "base-nova"`), not Radix. Custom triggers use the `render` prop (`<Button render={<Link href="..." />}>`), not `asChild`. See `AGENTS.md` for the scaffold's own warning about Next.js API drift from training data (async `params`/`searchParams`, etc.) — check `node_modules/next/dist/docs/` when something behaves unexpectedly.

## Architecture

- **Content lives in `content/`**, not in route files: `content/cv.md` (the homepage/CV source) and `content/guides/*.md` (6 files — 3 topics × EN/TR pairs). Both are parsed with `gray-matter` (`lib/cv.ts`, `lib/guides.ts`) and rendered with `next-mdx-remote/rsc`'s `MDXRemote`, using the shared component map in `lib/mdx-components.tsx`.
- **`CV.md` is MDX, not plain Markdown**: prose sections (About, Publications, Organizations, Contact) are plain Markdown; structured sections (Education, Experience, Projects, Skills) embed typed shortcode components (`components/mdx/education-entry.tsx` etc.) directly in the content, e.g. `<EducationEntry degree="..." institution="..." dates="..." />`. This avoids a hand-rolled section parser — the MDX component props _are_ the structured data.
- **`MDXRemote` needs `blockJS: false`** in its `options` (see `components/cv-page-content.tsx`) because `next-mdx-remote` blocks JS-expression props (`bullets={[...]}`) by default as an anti-injection guard for untrusted CMS content. Since `content/` is our own trusted source, this is safe — but forgetting it silently drops those props (they become `undefined`, not a build error, until something tries to `.map()` them).
- **Guides** (`lib/guides.ts`): `getGuide(slug)` reads frontmatter + computes a TOC from `## ` headings via `github-slugger` (same slug algorithm as the `rehype-slug` plugin used to render them, so TOC hrefs match rendered heading ids). `table_mode: catalog` guides (2 of 6 pairs) have zero H2 headings — `app/[slug]/page.tsx` skips the sidebar TOC for them. Two guides (`digital-entrepreneurship-guide`, `dijital-girisimcilik-rehberi`) omit `alternate_en`/`alternate_tr` frontmatter; `getAlternateHref()` supplies the same fallback URLs the old Jekyll layout defaulted to.
- **Guide permalinks are flat, not locale-prefixed**: `app/[slug]/page.tsx` is a single dynamic route with `generateStaticParams` returning all 6 slugs (e.g. `/ai-development-tools/`, `/ai-gelistirme-araclari/`). `next.config.ts` sets `trailingSlash: true` to match. `app/blog/` and the legacy `app/cv/` alias are separate static route folders, so there's no collision with the dynamic segment.
- **Shared header, not a root-layout global**: `components/site-header.tsx` is rendered by each top-level route component individually (home, blog, legacy CV alias, guide), not from `app/layout.tsx`. This is deliberate — the blog page needs to thread live `lang` state into the header's language toggle, while guide pages supply their sibling-language URL. The header always renders Home and Blog on the left; the optional language toggle and theme toggle appear on the right.
- **`LanguageToggle` has two modes** (`components/language-toggle.tsx`): `{ mode: "link", currentLang, alternateHref }` for guide pages (navigates to the sibling-language guide via `next/link`), or `{ mode: "toggle", lang, onToggle }` for the blog index (flips in-page panels). English-only pages omit the language toggle.
- **The blog index renders both languages and toggles visibility client-side** (`hooks/use-language-toggle.ts`). It starts in English on every page mount and keeps the selection local to the current blog page; both language panels stay in the DOM for SEO/crawlability rather than only the active one.
- **Theme**: `next-themes` (via `components/theme-provider.tsx`, generated by the shadcn scaffold), not a hand-rolled script — replaces the old `assets/theme.js`. Handles the flash-prevention blocking script and `prefers-color-scheme` fallback automatically.
- **CV page structure**: `components/cv-page-content.tsx` renders the shared MDX body for the homepage and the legacy `/cv/` alias; the alias points its canonical metadata to `/`. `components/cv-sub-header.tsx` is a desktop-only (`hidden lg:block`) sticky secondary nav listing the section anchors defined in `CV_SECTIONS`. Section anchor ids come from the MDX component ids — keep those ids aligned with `CV_SECTIONS` or the links will silently stop matching.
